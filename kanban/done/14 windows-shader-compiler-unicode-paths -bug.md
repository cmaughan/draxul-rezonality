# Compile shaders under international paths on Windows

**Summary:** Let projects whose paths fall outside the Windows active code page compile instead of failing every shader build.

**Priority:** P1 — international project paths prevent shader compilation on Windows.
**Source:** `plugins/rezonality/src/live_project.cpp`  
**Found during:** `kanban/done/13 international-project-path-serialization -bug.md`

**Evidence and trigger:** `run_process` starts the bundled `tools/win/glslangValidator.exe` with `CreateProcessW`, but the executable imports `_configure_narrow_argv`/`__p___argv`, so the CRT converts its arguments through the active code page. Shader, include, and output paths containing characters the code page cannot represent (for example CJK or emoji under code page 1252) reach the compiler as `?` and the candidate fails with a compile diagnostic. Since card 13 this fails safely and keeps the active scene; it no longer terminates the application. The temporary output directory has the same exposure when the user profile name is not representable.

- [x] **Investigate (choice):** Chose the project-relative invocation. The bundled executable already embeds a manifest (`asInvoker` only), so a side-by-side `activeCodePage=UTF-8` manifest would be ignored, and rebuilding or patching the vendored binary, or adding an in-process glslang, is a larger change. Process launch now lives in `src/shader_compiler.cpp` (card 01). On Windows the compiler runs with `lpCurrentDirectory` set to the project (passed as UTF-16), receives the project-relative shader path and `-I.`, and its output path is spelled absolute or project-relative, whichever round-trips through the active code page (`native_argument_encodable`). glslang reports project-relative names, which are resolved against the project before they become diagnostics. When no spelling is representable (for example, `TMP` under an unrepresentable profile with the project elsewhere), the candidate fails with an actionable "set TMP/TEMP" diagnostic instead of a garbled compile error.
- [x] **Investigate (Windows confirmation):** Confirmed ANSI code page 1252 via `GetACP`; rebuilt explicit-UCN CJK/accented fixtures and existing emoji fixtures passed the real compiler and dynamic-module suites on 2026-10-08. Both rebuilt objects contain the intended CJK UTF-8 bytes.
- [x] **Fix:** Shaders compile from accented, Asian, and emoji project paths through the project-relative invocation, and macOS keeps its absolute invocation and diagnostic paths. On macOS, `Rezonality bundled compiler builds international projects` drives the real compiler in both the native policy and a forced project-relative policy with an ASCII-only encodability predicate. That predicate simulates a code page that cannot represent the project, and the forced run covers include resolution beside the shader and from the project root, plus diagnostic paths. The Windows native case now passes locally with the real code-page path and encoding-independent test literals.
- [x] **Acceptance:** Removed the Windows tolerance from `The staged Rezonality module opens and reloads international project paths`; it now requires `ready` on every platform.
- [x] **Validation:** Earlier macOS aggregate/smoke passed. Windows (2026-10-08): rebuilt project suite passed (13.30 s), strict dynamic-module suite passed (85.53 s), seven golden comparisons passed, and paired fresh-profile same-cache Debug smoke passed. Earlier passing tests are not true-CJK evidence; the corrected, rebuilt fixtures and their passing suites above are.
