# Retire one-time Rezonality Vulkan texture staging

**Summary:** Release temporary texture-upload memory after the graphics card has finished using it so Rezonality on Windows does not retain unnecessary copies of static images.

**Source:** `plugins/rezonality/src/native_backend_vulkan.cpp`  
**Priority:** P2; static, high confidence. **Reported by:** Claude, Codex. Lines 556–559 and 634–638 retain mapped staging buffers after one-time texture upload at 1875–1881 and 1934–1973; lines 2206–2223 retire whole generations only. A 4096² RGBA buffer represents 64 MiB of staging by arithmetic, not an observed allocation.

- [x] **Baseline:** Measure static staging bytes after initial frames, after reload, and at generation retirement.
  - Confirmed in source: `create_surface()` and `create_model_texture()` keep a persistently mapped `HostSequentialWrite` staging buffer per static image and per model material texture, and `initialize_generation_images()` copied from it once but left it owned by the resource until `destroy_generation()`. For `examples/pbr_robot` that is the full image/texture pixel payload of every live generation (the Metal measurement of the same scene's asset bytes is ~817 MB including vertices/indices; the staging share is its texture portion).
  - Measured on RTX 3070 by the strict isolated native test: `retained_upload_staging_bytes` is 813,695,008 after initial activation, zero after the submitting fence completes and its slot retires, zero through eight size-only resizes, 813,695,008 after source replacement, then zero again after completion/retirement. This is actual one-time staging, not total retired GPU-memory peak.
- [x] **Implement:** Retire completed one-time upload buffers with their submitting frame slot; retain streaming audio buffers.
  - After recording each static surface or model-texture copy, `initialize_generation_images()` moves the staging buffer into `BackendState::retired_uploads` tagged with the recording frame slot. `retire_completed_slot()` (called when that slot's previous submission has completed, the same contract as generation retirement) destroys it. Audio surfaces' per-slot `audio_upload_buffers` are unchanged. Backend teardown destroys any pending uploads before the allocator.
  - Slots outside the 64-bit retirement mask keep the buffer on its resource, which releases it at generation retirement as before.
  - With card `04 rezonality-resize-generation-reuse -perf.md`, static images and model textures are shared across size-only generations, so a resize neither re-creates nor re-retains their staging.
- [ ] **Functional safety:** Cover aborted recording, failed submit, in-flight completion, and visible texture integrity.
  - Successfully submitted uploads: the native regression confirms the other slot's retirement does not release staging, and the submitting slot's fence/completion notification releases it while subsequent readbacks remain identical.
  - Aborted recording: the strict real-device hidden diagnostic now reproduces invalid layouts after discarding the first upload. Static images are marked initialized during recording, never uploaded, then shared into a target-only replacement after their staging is retired. `VUID-vkCmdDraw-None-09600` reports model textures still `UNDEFINED` when sampled. This is not a driver `vkQueueSubmit` failure injection; actual failed-submit coverage and a correct recovery contract remain open.
- [x] **Compare:** Require static staging to return to steady baseline after upload completion.
  - Verified on Windows: 813,695,008 bytes return to zero after each initial/reload submitting fence and matching slot-retirement notification; resizing reintroduces no staging. Streaming audio buffers are excluded by design. This successful-submission result does not establish aborted-upload safety.

  - Metal inspected: static images and model textures are created `MTLStorageModeManaged` and filled with `replaceRegion`, so there is no plugin-owned staging buffer to retire (the Metal resize test asserts `retained_upload_staging_bytes == 0`). On discrete-GPU Macs the driver keeps a managed CPU mirror; moving to private textures with a blit upload would be a separate change.

### Aborted-recording / rejected-submission blocker

Source inspection shows that `initialize_generation_images()` sets each static image/model texture's `initialized` flag while recording and moves its staging into `retired_uploads`. If that command buffer is discarded before submission, the GPU never executes the upload. The renderer's `flush_submit_chunk()` failure path replaces synchronization, `abort_active_frame()` requests swapchain recreation, and `recreate_frame_resources()` increments the target generation. Rezonality classifies that target-only change as `ReuseAssets`, preserving those initialized-but-never-uploaded static images. A subsequent slot-retirement notification can free their only upload buffers. The strict isolated real-device diagnostic now confirms invalid sampled-image layouts for this discarded-command-buffer sequence. It does not inject an actual driver submission error or exercise the renderer's failure hook end to end.
